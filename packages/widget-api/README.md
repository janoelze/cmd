# @cmd/widget-api

What a cmd widget is written against: API 1 of cmd's widget packages ([docs/56](../../docs/56-widgets-v3.md)). A widget is a React component made of this package's elements, reading cmd through its hooks and the `cmd` object. It runs in a process of its own; cmd draws it with its own kit, so it looks and behaves like a built-in window.

```tsx
import { Window, View, List, ListRow, ListRowContent, useAgents, cmd } from "@cmd/widget-api";

export default function Agents() {
  const agents = useAgents();
  return (
    <Window status={`${agents.length} agents`}>
      <View>
        <List>
          {agents.map((a) => (
            <ListRow key={a.id} onClick={() => a.windowId && cmd.windows.select(a.windowId)}>
              <ListRowContent title={a.name} detail={a.statusLine} />
            </ListRow>
          ))}
        </List>
      </View>
    </Window>
  );
}
```

- **A package** is a folder with a `package.json` whose `cmd` block names its widgets and the permissions it asks for (`cmd widget check` reads it). [`packages/widgets/agents`](../widgets/agents) is one, built into cmd.
- **Tests** run without a browser or cmd: `render(<Widget />, createHost({ agents: [...] }))` from `@cmd/widget-api/testing` gives the tree, with `press`, `choose` and matchers (`toHaveSection`, `toHaveRow`, `toShowState`).
- **Within API 1** nothing below changes or goes; additions say `@since 1.x`.

## Reference

API 1, minor 3. Everything here is in API 1 for good; what came after 1.0 says `@since 1.x`, and a widget that also runs on an older cmd checks `cmd.env.has(name)` first (a verb or an element).

### `cmd`

cmd, as a widget sees it. Reads run at once within the widget's grant; acts (1.1) ask the person (docs/55), only right after they pressed something in the widget, and only in its own workspace. Every method is async and rejects with an `ApiCallError` when the grant lacks what it needs (`error.permission` names it) or the person says no (`code: "denied"`).

### Frames

A frame widget's page (`"surface": "frame"`, its `view.html`) has a `cmd` of its own, typed by `@cmd/widget-api/frame` (`/// <reference types="@cmd/widget-api/frame" />`): every verb above, by the same name and with the same permissions, limits and asks; no hooks. A verb that needs a press (an act, `windows.open`) works right after a click in the frame, once per click. The page has no network of its own: its data comes through `cmd`.

#### `Frame`

| Prop | Type | What |
